# Plan: adopt the new application icon everywhere

Date: 2026-11-28
Status: Implemented on `feat/app-icon`.

## Problem

The icon set dated from XMMS 1.2.11: a hand-drawn 16x16 window icon, a
400x137 wordmark banner in the About dialog, wordmark backgrounds in the
Spectrum analyzer and Blur Scope plugins, and the "XMMSystem" launch tile of
`wmxmms`. The Debian package shipped one 16x16 hicolor icon for the desktop
entry. On HiDPI desktops each of these is upscaled, which makes it blurry.

## Cause

Two separate limits:

- **Size.** `mainwin_set_icon()` published a single 16x16 pixmap through
  `WM_HINTS` (and the `KWM_WIN_ICON` hint). Panels scale from
  `_NET_WM_ICON`, which was never set, so they fell back to the legacy
  pixmap. The hicolor theme held one 16x16 file for the same reason.
- **Artwork.** The other sites draw at their native size, so they were
  dated rather than blurry, but they belong to the same icon set.

## Decision

`xmms/app-icon.png` is the master for the whole set. The artwork is an
irregular, noisy raster (about 12,300 distinct colours; block pitch drifting
between 29 and 36 px), not a clean pixel grid, so renditions are
Lanczos-resampled to each target size and reduced to a 256-colour palette
(worst channel error 4/255 against the resampled master). The black
background is kept opaque, as delivered.

| Consumer | File | Rendition |
| --- | --- | --- |
| Window icon | `xmms/xmms_mini.xpm`, `xmms/xmms_icon_{32,48,64,128}.xpm` | 16 px legacy hints plus the `_NET_WM_ICON` list |
| About dialog | `xmms/xmms_logo.xpm` | 128x128 |
| Spectrum analyzer background | `Visualization/sanalyzer/xmms_logo.xpm` | icon centred on black, 250x100 |
| Blur Scope background | `Visualization/blur_scope/xmms_logo.xpm` | icon centred on black, 256x128 |
| `wmxmms` launch tile | `wmxmms/wmxmms.xpm` | 48x48 |
| Desktop entry | `packaging/icons/hicolor/<S>x<S>/apps/xmms.png` | 16 to 512 px |

- Every existing file name, C symbol name, and the XPM `#include` mechanism
  stay as they were; only the pixel data changed. `xmms/xmms.desktop` and
  `xmms/xmms.wmconfig` keep resolving `xmms_mini.xpm`.
- `mainwin_set_icon()` keeps the `WM_HINTS` and `KWM_WIN_ICON` paths for
  window managers that predate `_NET_WM_ICON`, and additionally publishes the
  five renditions through `gdk_window_set_icon_list()`.
- The visualization backgrounds now match their windows (`WIDTH` x `HEIGHT`).
  Both were 275x116 for windows of 250x100 and 256x128, so the old logo was
  cropped; a centred square icon would have sat off-centre.
- `packaging/debian/rules` installs the hicolor set and
  `packaging/debian/xmms.install` ships `usr/share/icons/hicolor/`. The
  package no longer installs a 16x16 XPM.

Left untouched on purpose: `wmxmms/xmms-dock-master.xpm` (the
remote-control sprite shown while XMMS runs, not the app icon),
`docs/images/xmms.png` (a screenshot), and `Input/mikmod/mikmod.xpm`
(MikMod's own logo).

`tools/generate-app-icon.py` derives every rendition from the master. It
needs Pillow, so the build never runs it; the output is committed and
`--check` reports a stale or missing rendition.

## Constraints honored

- No plugin ABI, socket framing, configuration path, or skin change.
- `gdk_pixbuf_new_from_xpm_data()` is deprecated since gdk-pixbuf 2.44, so
  the pixbufs come from the `gdk_pixmap_create_from_xpm_d()` path the window
  icon already used, read back with `gdk_pixbuf_get_from_drawable()`.
  `xmms/main.c` reports the same 25 pre-existing compiler diagnostics before
  and after.
- Build metadata follows `CONTRIBUTING.md`: the `.am` sources were edited
  and the shipped `Makefile.in` files mirrored by hand. Automake was not
  run; the shipped files are automake 1.9.6 output.

## Tests

- New `tests/test-app-icon.c`: spawns the real binary on a private Xvfb with
  an isolated `HOME` and `TMPDIR` and asserts that `_NET_WM_ICON` lists
  exactly the 16, 32, 48, 64, and 128 px square renditions in that order,
  that each holds rendered content, and that `WM_HINTS` still carries a
  16x16 pixmap and a 1-bit 16x16 mask.
- `tests/test-package-recipes.sh` checks that the master, the generator, the
  thirteen hicolor icons, and the regression test are distributed, that both
  `Makefile.am` and `Makefile.in` carry the new rules, that the Debian recipe
  installs the set, and that the visualization backgrounds match their
  window sizes.
- Runtime check under Xvfb: `_NET_WM_ICON` pixels are identical to the
  themed artwork at 16, 48, 64, and 128 px; the About dialog and both
  visualization windows were inspected in screenshots.
- `wmxmms` was verified to load the new tile (both dock windows are 64x64
  with a 48x48 shape, identical to the old icon) but could not be inspected
  visually: with or without the new artwork it does not paint its launch tile
  on a window-manager-less Xvfb.
