# BUG-2026-07-29T215100: clean GCC 15 builds reject legacy callbacks

## Problem

A clean source-tree build on GCC 15 failed on historical GTK callback signatures,
although the Debian package recipe already carried a compatibility setting. A
release must build consistently through both the normal source and Debian paths.

**Security impact: NONE.** No security exploit path was identified.

## Root Cause Analysis

1. **Reproduce:** A clean `./configure --disable-esd` followed by the Xvfb test suite failed on incompatible callback pointer types.
2. **Isolate:** The shared configure-time GCC flags did not include the compatibility option; only the Debian recipe did.
3. **Hypothesize:** Current GCC promotes this legacy callback diagnostic to an error unless the warning is explicitly made non-fatal.
4. **Verify:** A release-tools regression check failed before the change and passed after the option was added to both source and shipped generated configure metadata. A clean test suite and distcheck then completed.

**Risk level: Medium.** The defect blocks current compiler builds but does not alter runtime behavior.

## TDD Fix Plan
